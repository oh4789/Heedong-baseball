## TOP1 — 희동이 피격 플래시 + 미세 리코일(수신 측)

| 항목 | 내용 |
|---|---|
| ① 원칙 | 타격감은 공격 측(파티클·SFX·카메라)만으로는 부족. **맞은 쪽**이 짧게 하얗게 번쩍이고 미세히 밀려야 ‘베개 치기’가 사라진다. 플래시=누가 맞았는지, 리코일=힘이 어디로 갔는지. |
| ② 출처 | https://uhiyama-lab.com/en/notes/unity/unity-game-feel-hit-feedback/ (2026-07, receiver flash vs attacker particles) · https://www.socratopia.app/library/game-design-compelling-en/chapter-13 (reactive recoil) |
| ③ 희동이 적용점 | Perfect/Good 시 **희동이 실루엣**만 50–80ms 화이트 플래시 + 1–3px 뒤로 밀림 후 스프링 복귀. Trauma²(카메라)·히트스톱(시간)·juice 예산(배트/공 파티클)과 **다른 레이어**. |
| ④ 구체안 | (1) Perfect: 플래시 강 + 리코일 약간↑. Good: 플래시만. Miss: 없음. (2) 불꽃 회피 성공 시엔 희동이 플래시 금지(위협 레인과 혼선 방지). (3) 공유 머티리얼 함정 피하고 개체별 플래시만. (4) 모션 민감 옵션에서 리코일만 끄기 가능. |
| 판정/규칙 변경 | **없음** (보스 연출만). |

## TOP2 — VFX 4레인 가독성(위협 vs 임팩트 분리)

| 항목 | 내용 |
|---|---|
| ① 원칙 | 화면이 밝아도 안 읽히면 불공정해 보인다. 레인 4개(위협 텔 / 임팩트 확인 / 상태 / 분위기)가 **같은 대비 피크를 나눠 쓰지 않게**. 임팩트는 짧고 좁게, 텔은 길고 선명하게. |
| ② 출처 | https://gamineai.com/blog/top-down-combat-vfx-readability-2026-color-timing-system-busy-screens (2026) |
| ③ 희동이 적용점 | 불꽃 텔(레인1)과 Perfect 플래시·스파크(레인2)가 겹치면 ‘다음 구’가 안 보인다. juice **강도** 예산표와 다르게 **역할·타이밍·커버리지** 폴리시. |
| ④ 구체안 | (1) 불꽃/위험=위험 색 패밀리 전용, 플레이어 Perfect 플래시=다른 색 대역. (2) 임팩트 피크 40–90ms, 뷰포트 점유 ≤약 15%. (3) 텔 onset 120–220ms 유지, 임팩트가 텔 모양을 덮지 않게. (4) 디자이너용 1장: 레인 ID + ms + 끄기 옵션(분위기 레인4). |
| 판정/규칙 변경 | **없음** (VFX 폴리시만. 모양언어·색=회피전용[제안]과 별개). |

## TOP3 — 공 그림자 크기·오프셋으로 접근 깊이 큐

| 항목 | 내용 |
|---|---|
| ① 원칙 | 움직이는 그림자는 깊이·접근을 읽게 한다. 공 자체 크기만으로는 부족한 타이밍 감각을 **그림자만**으로 보강(규칙 창은 그대로). |
| ② 출처 | Kersten et al. moving cast shadows / depth (요약: https://www.cns.nyu.edu/csh/csh04/Articles/Kersten-etal-97.pdf) · 인터셉션·TTC 연구 맥락의 그림자·크기 큐 |
| ③ 희동이 적용점 | 드래그·릴리즈 스윙에서 ‘언제 올지’ 읽기. 티핑(구종)·모양언어(레인 형태)·BeatWarping과 직교인 **깊이 레이어**. |
| ④ 구체안 | (1) 홈플레이트 쪽 타원 그림자: 접근할수록 커지고 공–그림자 간격 좁아짐. (2) 불꽃구만 그림자 가장자리 잔불/일렁임(구종 색 중복 최소화). (3) 저사양: 그림자 스케일만, 블러 OFF. (4) 판정 박스·창 수치와 무관—연출 파라미터만. |
| 판정/규칙 변경 | **없음** (비주얼 큐만). |
